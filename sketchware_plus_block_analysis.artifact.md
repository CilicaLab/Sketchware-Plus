# Sketchware Plus Block System Analysis

This document provides a comprehensive breakdown of how blocks, parameters, and logic flows are structured in Sketchware Plus and how they translate to standard Android source code.

## 1. Block Parameter Specifiers

Parameter specifiers in the `spec` field of a block define the UI input type and the underlying data type.

| Specifier | Internal Type | Mapping UI Component / Context |
| :--- | :--- | :--- |
| `%b` | `boolean` | Boolean Toggle / Boolean Expression |
| `%d` | `double` | Number Input / Numeric Expression |
| `%n` | `double` | Number Input (Alias for %d) |
| `%s` | `String` | Text Input / String Expression |
| `%s.inputOnly` | `Input` | Basic Text Input (no block nesting) |
| `%s.inputCode` | `Input` | Multi-line Code Input |
| `%s.import` | `Input` | Import Statement Input |
| `%a` | `Map` | Map Variable Selector |
| `%l` | `List` | List Selector (`ListMap`, `ListString`, `ListInt`) |
| `%v.<type>` | `View` | Specific View ID Selector (e.g., `%v.button`) |
| `%m.<type>` | `Menu` | Dropdown Selector for various types (detailed below) |

### Common `%m` (Menu) Type Mappings:
- **`%m.view`**: General View ID selector.
- **`%m.imageview`**: ImageView selector.
- **`%m.intent`**: Intent Component selector.
- **`%m.color`**: Color Picker (supports HEX, `R.color.*`, and Material `R.attr.*`).
- **`%m.activity`**: Activity/Context selector (maps to `Context` or `ActivityName.this`).
- **`%m.resource`**: Drawable/Image resource selector.

## 2. Block Logic & AST Chains

The Abstract Syntax Tree (AST) for block logic is formed by linking `BlockBean` objects.

### Flow Control
- **Sequential Execution (`nextBlock`)**: Blocks are executed top-down. Each block stores the ID of the block following it.
- **Conditional Branches (`subStack1` / `subStack2`)**:
    - **`if`**: `subStack1` contains the blocks inside the `if` body.
    - **`ifElse`**: `subStack1` is the "True" branch; `subStack2` is the "Else" branch.
- **Loops**:
    - **`forever`**: `subStack1` contains the blocks to be repeated infinitely (`while(true)`).
    - **`repeat`**: `subStack1` contains the blocks repeated for a specific count.

### Functionality & Calls
- **MoreBlock calls (`definedFunc`)**: Invokes a user-defined function. It uses the `spec` as the method signature and `parameters` as arguments.
- **Raw Code Injection (`addSourceDirectly`)**: Known as "ASD" blocks. These emit the parameter string directly into the Java source file without transformation.
- **Argument Retrieval (`getArg`)**: Used inside MoreBlocks to access parameters passed to the function.

## 3. Component & Variable Inventory

Sketchware Plus manages a variety of built-in components and variables stored in the project data (`eC.java`).

### Data Variables
- **Primitive**: `boolean`, `double` (Number), `String`.
- **Collections**: `Map` (`HashMap<String, Object>`), `ListString`, `ListInt`, `ListMap`.

### Standard Components
- **Core**: `Intent`, `SharedPreferences`, `Timer`, `Calendar`, `Vibrator`, `Dialog`.
- **Media**: `MediaPlayer`, `SoundPool`, `TextToSpeech`, `SpeechToText`.
- **Networking**: `RequestNetwork` (OkHttp based), `BluetoothConnect`.
- **Firebase**: `FirebaseDB`, `FirebaseAuth`, `FirebaseStorage`, `FirebaseCloudMessage`.
- **Advanced**: `ObjectAnimator`, `Gyroscope`, `LocationManager`, `FilePicker`, `Camera`.

## 4. Code Mapping (Block to Java/Kotlin)

The following table shows how block chains are translated into source code by the `Fx.java` generator.

| Block / OpCode | Generated Java Code Snippet |
| :--- | :--- |
| `setVarInt` | `variableName = value;` |
| `ifElse` | `if (condition) { ... } else { ... }` |
| `forever` | `while(true) { ... }` |
| `viewOnClick` | `view.setOnClickListener(new View.OnClickListener() { ... });` |
| `intentSetScreen` | `intent.setClass(getApplicationContext(), TargetActivity.class);` |
| `fileSetData` | `prefs.edit().putString(key, value).commit();` |
| `doToast` | `SketchwareUtil.showMessage(getApplicationContext(), "msg");` |
| `addSourceDirectly` | `/* User's custom raw code */` |

## 5. View & Attribute Binding

View references are resolved either via `findViewById` or **ViewBinding** (if enabled).

- **ViewBinding Path**: `binding.viewId` (generated by `ViewBindingBuilder`).
- **Legacy Path**: `_viewId` or direct object reference.
- **Attribute Whitelist**: Only attributes defined in `AttributeConstants.java` (e.g., `translationX`, `alpha`, `background`) are safely modifiable via the AI Assistant and core logic.

## 6. Manifest Model & Generation (`Ix.java` AST)

Sketchware treats the `AndroidManifest.xml` not as a static file, but as a generated output derived from the project's metadata state.

### Manifest Components
| Component | Source of Truth | Logic Generator (`Ix.java`) |
| :--- | :--- | :--- |
| **Permissions** | `jq` bitmask + `permission.json` | Generates `<uses-permission>` tags. |
| **Activities** | `ProjectFileBean` list | Automatically creates `<activity>` tags for each screen. |
| **Activity Config** | `ProjectFileBean` properties | Maps orientation, keyboard state, and theme to attributes. |
| **Launcher** | `AndroidManifestInjector` lookup | Attaches `MAIN`/`LAUNCHER` intent-filters to the selected start activity. |
| **Features** | `jq` boolean flags | Injects metadata for Firebase, AdMob, Google Maps, etc. |

### Manifest Injection Points
Users can "patch" the generated manifest using structured injections:
1. **Application Attributes**: Custom XML attributes added to the `<application>` tag.
2. **Activity Attributes**: XML attributes added to a specific `<activity>` tag (e.g., `windowSoftInputMode`).
3. **App Components**: Raw XML blocks inserted into the `<application>` body for custom Services or Providers.
